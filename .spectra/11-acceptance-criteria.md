# 11 · Criterios de aceptación
Los enlaces son declaraciones de trazabilidad. La ejecución y su alcance se registran en docs/brownfield/verification.md.
- AC-001 · US-001 BR-001 OP-001 SK-001 WF-001: DADO un texto Makro conocido, CUANDO se interpreta, ENTONCES pesos, cantidades, IVA y base concuerdan. Evidencia existente: tests/test_makro_parser.py, tests/test_api.py.
- AC-002 · US-001 BR-002 INV-002 OP-001 POL-001 SK-001 WF-001: DADO texto con fecha/total ausentes o formato desconocido, CUANDO se interpreta, ENTONCES se devuelven campos pendientes. Evidencia parcial: tests/test_api.py::test_parse_endpoint_unknown_ticket; los casos de fecha/total faltantes no tienen prueba negativa dedicada.
- AC-003 · US-002 BR-003 BR-004 INV-003 OP-002 POL-002 SK-002 WF-002: DADOS tickets y alias, CUANDO se ingieren, ENTONCES se conservan líneas, se aprenden alias y se crean revisiones. Evidencia existente: tests/test_ingestion.py. Ejecución SQLite; no certifica PostgreSQL ni aislamiento.
- AC-004 · US-003 OP-004 POL-003: DADA familia autenticada, CUANDO crea o confirma y consulta una compra, ENTONCES la API persiste y devuelve solo su compra. Evidencia 0.2.0: tests/test_receipt_api.py; PostgreSQL real en tests/test_postgres.py solo cuando se ejecuta en entorno dedicado. Prototipo visual sin integrar.
- AC-005 · US-004 BR-005 BR-006 INV-001 INV-002 OP-003 POL-004 AG-001 SK-003 WF-003: DADO el registro de 363 EUR, CUANDO se verifica, ENTONCES las bases y los grupos fiscales cuadran y fecha/BD/existencias siguen pendientes. Control reproducible: scripts/verify_adoption.py.
- AC-006 · US-005 EVT-001 WF-004: DADA compra confirmada, CUANDO la API guarda el hecho interno y proyecta compras, ENTONCES reintentos no duplican evento ni inventario, y rollback no deja proyección parcial. Evidencia 0.2.0: tests/test_receipt_api.py; concurrencia PostgreSQL calificada por ejecución específica. Consumo de inventario y broker externo fuera de alcance.
- AC-007 · INV-004: DADAS familias A/B, CUANDO B normaliza o consulta, ENTONCES no resuelve productos/alias privados de A ni accede a sus compras/historial. El fallo histórico 0616d2b se conserva; cierre 0.2.0 en tests/test_family_isolation.py y tests/test_receipt_api.py.
- AC-008 · BR-007 INV-004: DADO token ausente, inválido, caducado o familia ajena, CUANDO accede a datos, ENTONCES se rechaza o devuelve 404 sin fuga. Evidencia: tests/test_receipt_api.py y tests/test_family_isolation.py.
- AC-009 · BR-008 INV-005: DADOS reintentos idénticos/conflictivos y fallos inducidos, CUANDO se guardan comandos, ENTONCES hay una compra/proyección o rollback íntegro. Evidencia: tests/test_receipt_api.py; PostgreSQL concurrente: tests/test_postgres.py cuando se ejecuta.
- AC-010 · BR-009 INV-005: DADO ticket sin fecha, CUANDO se almacena queda pendiente sin existencias; al confirmar con datos válidos conserva ID y proyecta una vez. Importes inválidos se rechazan independientemente de confianza. Evidencia: tests/test_receipt_api.py.

- AC-011 · US-006 BR-010 OP-005: DADAS ofertas sintéticas compatibles, CUANDO se comparan, ENTONCES IVA, kg/l/unidad, packs, peso variable y top tres se calculan sin rellenar candidatos. Evidencia: tests/test_shopping_comparison.py.
- AC-012 · US-006 BR-011 OP-005: DADOS precios de otra zona, viejos, ambiguos o fuentes caídas, CUANDO se compara, ENTONCES no son precios locales elegibles ni se inventa cobertura. Evidencia: tests/test_shopping_comparison.py, tests/test_price_provider.py y tests/test_mercadona_provider.py. Mocks califican lógica, no disponibilidad real de seis cadenas.
- AC-013 · US-007 INV-006 AG-002 OP-005: DADAS familias A/B y una cesta con cobertura parcial, CUANDO se actualiza o asesora, ENTONCES los datos están aislados, el plan respeta desembolso y no crea compras ni ahorro logrado. Evidencia: tests/test_shopping_api.py; UI compilada en web. Probar en móvil real y operación productiva sigue pendiente.
